Opus Brain — multi-agent supply-chain platform

Applied AI
0→1 in-house agent platform on AWS Bedrock
Problem

Customers wanted to run compliance audits, analytics and repetitive process work — over purchase orders, invoices and payment flagging — just by describing the task. But supply-chain objects live across separate apps, microservices and databases, and no off-the-shelf agent framework mapped onto that data model.

Approach

Designed an in-house multi-agent orchestrator on AWS Bedrock: a master planner decomposes each metaprompt, a tool-calling agent spawns a DAG of downstream calls, and validation agents verify the result before it's returned.

What I built

The tool-calling layer — knowledge retrieval, CRUD/GraphQL generation, code generation, and a memory manager that extracts entities for long-running tasks — plus the evaluation harness of deterministic checks and LLM-as-judge over golden datasets.

Trade-offs

Building in-house instead of adopting a framework was more upfront work, but it was the only way to fit the messy, distributed data model — and it gave full control over tooling, memory and evaluation.

Reactive report generation

Backend
~30% faster report runtime
Problem

Large CSV report generation was slow and blocking, tying up threads and delaying downstream delivery.

Approach

Rebuilt the pipeline around RxJava reactive streams — backpressure-aware, non-blocking, and streamed instead of buffered.

Trade-offs

Reactive code is harder to read and debug, so I invested in clear operator boundaries and metrics to keep it maintainable for the team.

Impact

~30% runtime reduction and steadier resource usage under load, with report SLAs consistently met.

RocksDB → Postgres re-architecture

Systems
Durable & queryable tracking store
Problem

A RocksDB-backed tracking layer was fast but opaque — hard to query, back up, and reason about during incidents.

Approach

Migrated the model to a Postgres-backed architecture with a schema built for the real access patterns and recovery needs.

Trade-offs

Traded raw embedded-KV speed for durability, ad-hoc queryability and operational simplicity — the right call for this workload.

Impact

Recovery and debugging became straightforward, and analytics could join directly against tracking data.

Data Eng
1TB+ daily, without OLTP strain
Problem

Approach

Designed a Redshift–Aurora integration with materialized views so heavy analytical reads hit the warehouse, not production.
