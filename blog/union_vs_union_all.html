UNION vs UNION ALL: Understanding the Performance Trade-offs

In the world of SQL optimization, few choices have as clear-cut a performance implication as the decision between UNION and UNION ALL. Let's dive deep into understanding these operators, their differences, and most importantly - when to use each one.

The Core Difference

UNION

Combines results and removes duplicates. Think of it as DISTINCT + Merge operation. This comes with additional computational overhead.

UNION ALL

Simply concatenates results. No duplicate removal. Fast and efficient. Perfect when you know your data won't have duplicates.

Database-Specific Implementations

PostgreSQL

  • UNION: Uses HashAggregate or Sort + Unique operator for deduplication
  • UNION ALL: Streams rows directly with no overhead

MySQL

  • Uses temporary tables for UNION operations
  • UNION ALL performs direct appends
  • Recent InnoDB improvements have enhanced performance

Data Warehouse Considerations

Redshift (OLAP)

In distributed systems like Redshift, UNION operations can be particularly expensive:

SELECT customer_id, order_id FROM sales_april
UNION
SELECT customer_id, order_id FROM sales_may;

This query requires data shuffling across nodes and deduplication, potentially taking minutes and consuming significant compute resources.

Aurora (OLTP)

For transactional databases, consider this common scenario:

SELECT txn_id, amount FROM debit_log
UNION ALL
SELECT txn_id, amount FROM credit_log;

Using UNION ALL here is optimal since transaction IDs are naturally unique.

Performance Implications

  • UNION Cost: CPU cycles, memory usage, potential disk I/O for sorting
  • UNION ALL Benefit: Simple append operations, minimal resource usage

Best Practices

  • Use UNION ALL when you can guarantee no duplicates
  • Use UNION ALL when duplicates are acceptable in the result set
  • Only use UNION when you absolutely need duplicate removal
  • Consider your database engine's specific implementation

Conclusion

The choice between UNION and UNION ALL can significantly impact your query performance. As a general rule, if you don't explicitly need duplicate removal, UNION ALL is almost always the better choice. It's faster, uses fewer resources, and scales better with large datasets.
